# 操作手册

> 本手册面向使用 OzonFlow 做 Ozon 平台 rFBS（卖家自发货）跨境直发的中国卖家团队：老板、运营、仓管（仓库）、客服、财务。按一天的真实工作顺序组织：先完成开始使用的准备，再按「每日开工 → 订单履约 → 商品与定价 → 库存 → 客服售后 → 财务 → 推广与价格 → 合规 → 自动化 → 审批 → 周报」逐章操作。
>
> 每个流程都写明 **目的、适用角色、前置条件**，再给出编号步骤。每一步配一张真实截图：**红框** 标出要点击的位置，紧跟一张点击后的结果图（含右上角的提示消息）。

## 阅读前须知

**线上地址**：<https://rong001.github.io/ozonflow-rfbs-app/>（打开即用，数据保存在当前浏览器的本地存储里，换浏览器或清缓存后需重新导入）。

**当前接入模式：免密钥模式。** 目前没有 Ozon Seller API 的 Client-Id / Api-Key，系统通过两种方式获取真实店铺数据：

1. **OzonFlow 连接器浏览器扩展**：在你已登录的 Ozon 卖家后台（seller.ozon.ru）页面里，读取后台自己加载的订单、结算、商品数据；不保存密码、不额外发请求。
2. **报表导入**：把卖家后台导出的订单 / 财务 CSV、XLSX 文件拖进「数据连接」页。

**需要人工完成的写操作（重要）**：在拿到 Api-Key 并部署 `server/ozon-proxy.js` 代理之前，下列动作在 OzonFlow 里点击后 **只更新 OzonFlow 内的状态与记录，不会写回 Ozon 平台**，必须由人在 Ozon 卖家后台同步完成：

| OzonFlow 里的动作 | 还需在 Ozon 卖家后台手动完成 |
|---|---|
| 申请面单（生成运单号） | 在物流商系统 / Ozon 后台实际下单取号、打印面单 |
| 发货 / 确认发货 | 在 Ozon 后台把订单标记为已发货（备货完成） |
| 回传运单号 | 在 Ozon 后台订单详情里填写运单号 |
| 改价、报名活动、暂停广告 | 在 Ozon 后台价格 / 促销 / 广告页面操作 |
| 发布商品、库存同步 | 在 Ozon 后台商品页上架、修改库存 |
| 回复评价 / 问答 / 买家聊天 | 在 Ozon 后台对应页面发送（另需 Premium Plus 订阅才能走接口） |
| 同意退款、取消订单 | 在 Ozon 后台退货 / 订单页处理 |

下文凡涉及以上动作的步骤，都会用「⚠ 人工完成」标出。

**界面速览**：左侧是可展开的图标侧栏（6 个分组：工作台 / 订单履约 / 商品增长 / 客服售后 / 财务风控 / 自动化与集成）；顶栏依次是页面标题、命令面板入口、经营场景、店铺、角色、同步状态、通知铃铛、使用手册（?）、重置当前场景、头像。

# 第一部分 开始使用

## 1.1 新手开店引导（向导）

- **目的**：第一次使用时 4 步完成冷启动：绑定店铺 → 选择 rFBS → 设置默认物流 → 导入首批商品。
- **适用角色**：老板、运营。
- **前置条件**：已在 Ozon Seller Center 开通 rFBS / 跨境直发权限。

**步骤**

1. 打开系统后进入「小白冷启动」经营场景时，向导自动弹出，停在第 1 步「绑定店铺」。顶部 4 个圆点显示进度。

   ![向导自动弹出](img/s-wizard-01-auto-open.png)

2. 在「店铺名称」填写你的 Ozon 店铺名。**免密钥模式下 Client-Id 和 Api-Key 可以留空**（系统只在本地记录，不直连 Ozon API）；以后拿到密钥请填到服务器代理里，而不是这里。点右下角 **「绑定并继续」**（红框）。

   ![填写店铺名称](img/s-wizard-02-fill.png)

3. 右上角提示「店铺已绑定」，进入第 2 步「选择履约模式」。默认选中「rFBS · 跨境直发」（FBO/FBS 当前账号未开通，不可选）。点 **「确认 rFBS」**。

   ![选择 rFBS](img/s-wizard-03-rfbs.png)

   > 注意：rFBS 备货时效通常 24–72 小时，超时会影响搜索排名与店铺健康。

4. 第 3 步「设置默认物流渠道」：点击一张渠道卡片（云途 / 燕文 / OGL 等，卡片上显示时效与每公斤单价）使其高亮，再点 **「保存物流」**。规则引擎会优先用这个渠道匹配轻小件。

   ![选择默认物流](img/s-wizard-04-logistics.png)

5. 第 4 步「导入首批经营商品」：预览将要加入刊登草稿的 3 个爆款，点 **「导入并完成」**。

   ![导入商品](img/s-wizard-05-import.png)

   > 注意：刊登前请补齐必填俄语属性：Бренд / Страна производитель / Состав。

6. 向导关闭并自动跳转到「刊登上架」，导入的商品出现在草稿列表中，可以继续映射、发布（见 3.3）。

   ![引导完成](img/s-wizard-06-done.png)

7. 回到「经营总览」，顶部开店进度卡显示 4 项全部完成。

   ![开店进度](img/s-wizard-07-dash.png)

8. 任何时候都可以从侧栏底部 **「开店引导」**（红框）重新打开向导；顶栏「经营场景」下拉里也有「打开开店引导」。

   ![重新打开向导](img/s-wizard-08-reopen.png)

## 1.2 选择经营场景（业务数据集）

- **目的**：系统内置三套业务数据集，分别对应三种经营阶段，可随时切换查看。
- **适用角色**：所有角色。
- **前置条件**：无。

| 经营场景 | 适合 | 特点 |
|---|---|---|
| 小白冷启动 | 刚开店 | 开店向导、少量 SKU、选品→刊登→出单完整闭环 |
| 旺季履约突击 | 出单高峰 | 爆款多、出单快、差评待回；9 个 Agent 默认启用 |
| 多店公司化 | 多店铺团队 | 三店真实分区、角色权限、周报与老板视角 |

1. 点击顶栏 **「经营场景」**（红框），下拉列出三套场景，以及「重置当前场景数据」「打开开店引导」两个操作。

   ![经营场景下拉](img/s-scene-01-dropdown.png)

2. 点「多店公司化」，右上角提示「已切换经营场景」，顶栏场景名、店铺和所有页面数据随之刷新。

   ![切换完成](img/s-scene-02-switched.png)

> 注意：切换场景会重新载入该场景的数据集，当前场景里做过的改动不会带过去。顶栏右侧的「↻」按钮可「重置当前场景数据」，清除本场景改动。

## 1.3 切换店铺

- **目的**：多店卖家在不同店铺间切换，订单、刊登、库存、评价、退货都按当前店铺过滤（真实分区）。
- **适用角色**：所有角色。
- **前置条件**：场景中有多家店铺（如「多店公司化」）。

1. 点击顶栏店铺名（带国旗，红框）。下拉列出所有店铺，每家显示「rFBS · N 单 · N 差评」。

   ![店铺下拉](img/s-shop-01-dropdown.png)

2. 点选另一家店铺，右上角提示「已切换至『店铺名』」，经营总览的 KPI、待办、趋势图都换成该店数据。

   ![切换店铺](img/s-shop-02-switched.png)

3. 进入「订单履约」，列表只显示该店订单。

   ![该店订单](img/s-shop-03-orders.png)

## 1.4 切换角色

- **目的**：不同岗位只看到自己需要的页面、只能执行自己权限内的动作。
- **适用角色**：所有人（一般由老板为团队成员说明各自角色）。
- **前置条件**：无。

| 角色 | 下拉提示 | 可见页面数 | 主要职责 |
|---|---|---|---|
| 老板 | 全权限 · 看周报 | 26 | 全部页面与动作；唯一可审批 |
| 运营 | 选品刊登履约 | 24 | 选品、刊登、定价、审单、客服、推广 |
| 仓管 | 仓配发货退货 | 9 | 采购完成、面单、发货、补货、退货 |
| 客服 | 评价问答退货 | 7 | 评价、问答、买家聊天、退货 |
| 财务 | 对账结算利润 | 12 | 利润定价、财务对账、店铺健康、推广与价格 |

1. 点击顶栏 **「角色」**（红框），下拉列出 5 个角色及职责提示。

   ![角色下拉](img/s-role-01-dropdown.png)

2. 选「仓管」，右上角提示「当前角色：仓管」，头像变为「仓」。把鼠标移到侧栏上可以看到只剩仓管可见的分组与页面。

   ![仓管侧栏](img/s-role-02-warehouse-nav.png)

3. 仓管尝试打开无权页面（例如通过命令面板去「财务对账」）时，系统提示「当前角色『仓管』无权访问『财务对账』」，页面不会切换。

   ![无权访问提示](img/s-role-03-denied.png)

4. 「财务」角色的侧栏：利润定价、财务对账、店铺健康，以及推广活动、价格竞争、平台集成、数据连接等。

   ![财务侧栏](img/s-role-04-finance-nav.png)

5. 「客服」角色的侧栏：客服评价、客服收件箱、退货异常，以及订单（只读）等。

   ![客服侧栏](img/s-role-05-cs-nav.png)

> 注意：角色控制的是「看得到什么、能点什么」。审批中心的「通过 / 驳回」只有老板能操作（见第十一部分）。

## 1.5 安装并连接 OzonFlow 连接器扩展（免密钥接入真实店铺）

- **目的**：没有 Api-Key 也能把 Ozon 卖家后台的真实订单、结算、商品数据带进 OzonFlow。
- **适用角色**：老板、运营、仓管、财务（谁登录卖家后台，谁装扩展）。
- **前置条件**：使用 Chrome 或 Edge 浏览器；有 Ozon 卖家后台登录账号。

1. 进入侧栏「自动化与集成 → 数据连接」。未安装扩展时，第一张指标卡显示「浏览器插件 · 未安装」（红框）。

   ![未安装状态](img/s-ext-01-not-installed.png)

2. 在「① Ozon 卖家后台直连」卡片里点 **「OzonFlow 连接器插件」** 链接（红框）下载 `ozonflow-connector.zip`，解压得到 `ozonflow-connector` 文件夹。

   ![下载扩展](img/s-ext-02-download.png)

3. 在浏览器地址栏打开 `chrome://extensions`（Edge 为 `edge://extensions`），打开右上角 **「开发者模式」**（红框），再点左上角 **「加载未打包的扩展程序」**（旧版浏览器显示为「加载已解压的扩展程序」，红框），选择解压出的文件夹。列表中出现「OzonFlow 连接器 1.0.0」即安装成功。

   ![chrome://extensions](img/s-ext-03-chrome-extensions.png)

4. 点击浏览器工具栏里的 OzonFlow 连接器图标，弹窗显示已捕获的订单 / 结算 / 商品数量，以及「打开 Ozon 卖家后台」「打开 OzonFlow 同步」「清空已捕获数据」三个按钮。

   ![扩展弹窗](img/s-ext-04-popup.png)

5. 回到 OzonFlow「数据连接」页（刷新一次），第一张卡变为 **「已连接 v1.0.0」**（红框）。

   ![已连接](img/s-ext-05-connected.png)

6. ⚠ 人工完成：在同一浏览器里正常登录 Ozon 卖家后台，依次打开 **订单、财务（结算 / 交易）、商品列表** 页面，扩展会在后台页面右下角显示已捕获数量（系统不会、也不能绕过 Ozon 登录）。

7. 回到「数据连接」，点 **「从插件同步」**（红框）。

   ![从插件同步](img/s-ext-06-pull-a.png)

   结果：已捕获数据时，订单并入「订单履约」（含状态、发货截止时间、临期标红），结算按订单号并入「财务对账」，并提示同步数量。**还没有在卖家后台捕获到数据时**，会提示「插件还没有捕获数据：请先在 Ozon 卖家后台打开订单或财务页面」，如下图：

   ![同步结果提示](img/s-ext-06-pull-b.png)

8. 点 **「刷新插件状态」** 可重新读取扩展的捕获计数，提示「插件状态已刷新」。

   ![刷新插件状态](img/s-ext-07-ping-a.png)
   ![刷新结果](img/s-ext-07-ping-b.png)

### 1.5.1 不装扩展：报表导入

1. 在 Ozon 卖家后台「订单 → 导出」或「财务 → 报告」下载 CSV / Excel。在「② 报表导入」卡片点 **「选择文件」**（红框），选择下载的文件。

   ![订单报表导入](img/s-imp-02-orders.png)

   ![并入订单履约](img/s-imp-04-merged.png)

### 1.5.2 物流轨迹与数据导出

# 第二部分 每日开工

## 2.1 看经营总览

- **目的**：开工 1 分钟了解今天最要紧的事。
- **适用角色**：所有角色（内容按角色与当前店铺显示）。
- **前置条件**：已选定店铺。

1. 顶部焦点区一句话给出今日重点（例如「今天先处理 3 单临近超时，4 项待审批」），下方显示 Agent 今日已处理数量、已启用 Agent 数，右侧是「AI 指令台」与「一键跑全部 Agent」。

   ![今日焦点](img/s-daily-01-hero.png)

2. KPI 卡（红框）：今日订单、待发货（含待采购）、超时风险（距截单 < 6h）、预估毛利（已扣退货拨备）、差评 / 退货。

   ![KPI 卡](img/s-daily-02-kpi.png)

3. 「今日待办」（红框）按风险排序：高风险审批、超时备货、待审单、缺货待采、差评待回、退货异常、物流轨迹异常、1★ 待升级、资金异常、刊登待处理。每项右侧按钮直达对应页面与筛选。

   ![今日待办](img/s-daily-03-todo.png)

4. 点顶栏 **铃铛**，弹出紧急事项汇总（超时 / 差评待回 / 退货异常）。

   ![铃铛提示](img/s-daily-04-bell.png)

## 2.2 处理今日待办

1. 在待办里点「N 笔超时备货」右侧的 **「去处理」**（红框）。

   ![去处理](img/s-daily-05-todo-risk-a.png)

2. 直达「订单履约 · 超时风险」，只显示距截单 < 6 小时的订单，按第三部分处理。

   ![超时风险筛选](img/s-daily-05-todo-risk-b.png)

3. 回到总览，点「N 项高风险动作待审批」右侧的 **「去审批」**（红框）。

   ![去审批](img/s-daily-06-todo-approval-a.png)

4. 直达审批中心待审批列表（处理方法见第十一部分）。

   ![审批中心](img/s-daily-06-todo-approval-b.png)

> 建议的每日顺序：超时风险 → 待审批 → 待审单 / 待采购 → 差评 → 退货 → 物流异常 → 刊登。

# 第三部分 订单履约（审核 → 采购 → 面单 → 发货 → 运单号回传）

- **目的**：把 Ozon 新订单在截单前发出，避免逾期发货率超标。
- **适用角色**：运营（审单、面单、发货）、仓管（采购完成、面单、发货）、老板；客服只读。
- **前置条件**：订单已通过扩展同步、报表导入或「同步订单」进入系统；物流渠道已连接。

订单状态流转：**待审核 → （待采购）→ 待发货 → 已发货**；剩余时效 ≤ 6 小时且未发货的订单自动标为「超时风险」。

## 3.7 超时风险处理

- **目的**：抢救距截单不足 6 小时的订单，控制逾期发货率（Ozon 阈值 ≤10%，7 天窗口）。
- **适用角色**：运营、仓管、老板。
- **前置条件**：存在超时风险订单。

1. 「订单履约 · 超时风险」（红框）：剩余时效标红。逐单按 3.4–3.5 申请面单并发货。

   ![超时风险列表](img/s-risk-01-list.png)

2. 批量抢救：打开「财务风控 → 店铺健康」，点 **「一键抢救临期订单」**（红框）。

   ![一键抢救](img/s-risk-02-rescue-a.png)

3. 超时抢救 Agent 执行「审单 → 面单 → 发货」，缺货的标记采购或送审取消，提示「超时抢救 · 处理 N 笔」。

   ![抢救结果](img/s-risk-02-rescue-b.png)

4. 节假日前在「时效物流」检查「仓库休息日对截单期影响」，按建议在休息日前发出或安排值班。

   ![休息日影响](img/s-risk-03-holiday.png)

5. 实在来不及的缺货单，取消申请会进入审批中心（取消会计入取消率），由老板决定。

   ![取消送审](img/s-risk-04-cancel.png)

### 常见问题（订单）

- **点「面单」后运单号和物流商的不一致？** 免密钥模式下系统生成的是内部跟踪号，请以物流商真实单号为准，在 Ozon 后台填写真实单号。
- **为什么「一键审单」后还有订单没过？** 金额 ≥ 5000₽ 或有买家留言的订单需要人工审核。
- **仓管看不到「审单」？** 审单属于运营权限；仓管负责采购完成、面单、发货。
- **订单详情里看不到「确认发货」？** 只有已有运单号且未发货的订单才显示该按钮，先申请面单。

# 常见问题

**Q1：数据存在哪里？换电脑后还在吗？**
数据保存在当前浏览器的 localStorage（键 `ozonflow_rfbs_v2`）。换电脑或清缓存后需重新通过扩展同步或导入报表。「数据连接 ⑦」可导出经营数据 JSON 备份。

**Q2：没有 Api-Key，哪些事情 OzonFlow 能做、哪些必须人工？**
读数据（订单、结算、商品、公开价格、物流轨迹）通过扩展和报表导入完成；所有写回 Ozon 的动作（发货、回传运单号、改价、上架、库存、回复、退款、取消、广告、报名活动）必须在 Ozon 卖家后台人工完成，见「阅读前须知」表格。

**Q3：扩展装好了，「从插件同步」却提示没有捕获数据？**
需在同一浏览器登录 seller.ozon.ru，并打开订单、财务、商品列表页面让后台加载数据；然后点「刷新插件状态」再同步。

**Q4：为什么点「通过」没有反应？**
只有老板角色能审批，其他角色按钮置灰。顶栏切到「老板」后再操作。

**Q5：Agent 会不会擅自改价、退款？**
不会。超过阈值的动作都进入审批中心；低于阈值的（如改价 ≤10%）会自动执行并写审计日志，可在审批中心底部查看。

**Q6：我改错了数据，怎么恢复？**
顶栏「↻」或「经营场景 → 重置当前场景数据」可恢复当前场景初始数据（会清除本场景所有改动）。

**Q7：报表导入识别为「未识别」？**
确认文件是 Ozon 后台原始导出、表头为俄文（如 Номер отправления / Тип начисления），CSV 分隔符为分号或逗号均可。

**Q8：页面右上角的提示一闪就没了？**
提示约 3 秒后自动消失，操作结果同时会体现在列表状态、审计日志或同步记录中。
