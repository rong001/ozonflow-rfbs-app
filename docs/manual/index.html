操作手册

本手册面向使用 OzonFlow 做 Ozon 平台 rFBS（卖家自发货）跨境直发的中国卖家团队：老板、运营、仓管（仓库）、客服、财务。按一天的真实工作顺序组织：先完成开始使用的准备，再按「每日开工 → 订单履约 → 商品与定价 → 库存 → 客服售后 → 财务 → 推广与价格 → 合规 → 自动化 → 审批 → 周报」逐章操作。

每个流程都写明 目的、适用角色、前置条件，再给出编号步骤。每一步配一张真实截图：红框 标出要点击的位置，紧跟一张点击后的结果图（含右上角的提示消息）。

阅读前须知

线上地址：https://rong001.github.io/ozonflow-rfbs-app/（打开即用，数据保存在当前浏览器的本地存储里，换浏览器或清缓存后需重新导入）。

当前接入模式：免密钥模式。 目前没有 Ozon Seller API 的 Client-Id / Api-Key，系统通过两种方式获取真实店铺数据：

  1. OzonFlow 连接器浏览器扩展：在你已登录的 Ozon 卖家后台（seller.ozon.ru）页面里，读取后台自己加载的订单、结算、商品数据；不保存密码、不额外发请求。
  2. 报表导入：把卖家后台导出的订单 / 财务 CSV、XLSX 文件拖进「数据连接」页。

需要人工完成的写操作（重要）：在拿到 Api-Key 并部署 server/ozon-proxy.js 代理之前，下列动作在 OzonFlow 里点击后 只更新 OzonFlow 内的状态与记录，不会写回 Ozon 平台，必须由人在 Ozon 卖家后台同步完成：

OzonFlow 里的动作 还需在 Ozon 卖家后台手动完成
申请面单（生成运单号） 在物流商系统 / Ozon 后台实际下单取号、打印面单
发货 / 确认发货 在 Ozon 后台把订单标记为已发货（备货完成）
回传运单号 在 Ozon 后台订单详情里填写运单号
改价、报名活动、暂停广告 在 Ozon 后台价格 / 促销 / 广告页面操作
发布商品、库存同步 在 Ozon 后台商品页上架、修改库存
回复评价 / 问答 / 买家聊天 在 Ozon 后台对应页面发送（另需 Premium Plus 订阅才能走接口）
同意退款、取消订单 在 Ozon 后台退货 / 订单页处理

下文凡涉及以上动作的步骤，都会用「⚠ 人工完成」标出。

界面速览：左侧是可展开的图标侧栏（6 个分组：工作台 / 订单履约 / 商品增长 / 客服售后 / 财务风控 / 自动化与集成）；顶栏依次是页面标题、命令面板入口、经营场景、店铺、角色、同步状态、通知铃铛、使用手册（?）、重置当前场景、头像。

第一部分 开始使用

1.1 新手开店引导（向导）

  • 目的：第一次使用时 4 步完成冷启动：绑定店铺 → 选择 rFBS → 设置默认物流 → 导入首批商品。
  • 适用角色：老板、运营。
  • 前置条件：已在 Ozon Seller Center 开通 rFBS / 跨境直发权限。

步骤

  1. 打开系统后进入「小白冷启动」经营场景时，向导自动弹出，停在第 1 步「绑定店铺」。顶部 4 个圆点显示进度。

  2. 在「店铺名称」填写你的 Ozon 店铺名。免密钥模式下 Client-Id 和 Api-Key 可以留空（系统只在本地记录，不直连 Ozon API）；以后拿到密钥请填到服务器代理里，而不是这里。点右下角 「绑定并继续」（红框）。

  3. 右上角提示「店铺已绑定」，进入第 2 步「选择履约模式」。默认选中「rFBS · 跨境直发」（FBO/FBS 当前账号未开通，不可选）。点 「确认 rFBS」。

    注意：rFBS 备货时效通常 24–72 小时，超时会影响搜索排名与店铺健康。

  4. 第 3 步「设置默认物流渠道」：点击一张渠道卡片（云途 / 燕文 / OGL 等，卡片上显示时效与每公斤单价）使其高亮，再点 「保存物流」。规则引擎会优先用这个渠道匹配轻小件。

  5. 第 4 步「导入首批经营商品」：预览将要加入刊登草稿的 3 个爆款，点 「导入并完成」。

    注意：刊登前请补齐必填俄语属性：Бренд / Страна производитель / Состав。

  6. 向导关闭并自动跳转到「刊登上架」，导入的商品出现在草稿列表中，可以继续映射、发布（见 3.3）。

  7. 回到「经营总览」，顶部开店进度卡显示 4 项全部完成。

  8. 任何时候都可以从侧栏底部 「开店引导」（红框）重新打开向导；顶栏「经营场景」下拉里也有「打开开店引导」。

1.2 选择经营场景（业务数据集）

  • 目的：系统内置三套业务数据集，分别对应三种经营阶段，可随时切换查看。
  • 适用角色：所有角色。
  • 前置条件：无。
经营场景 适合 特点
小白冷启动 刚开店 开店向导、少量 SKU、选品→刊登→出单完整闭环
旺季履约突击 出单高峰 爆款多、出单快、差评待回；9 个 Agent 默认启用
多店公司化 多店铺团队 三店真实分区、角色权限、周报与老板视角

  1. 点击顶栏 「经营场景」（红框），下拉列出三套场景，以及「重置当前场景数据」「打开开店引导」两个操作。

  2. 点「多店公司化」，右上角提示「已切换经营场景」，顶栏场景名、店铺和所有页面数据随之刷新。

注意：切换场景会重新载入该场景的数据集，当前场景里做过的改动不会带过去。顶栏右侧的「↻」按钮可「重置当前场景数据」，清除本场景改动。

1.3 切换店铺

  • 目的：多店卖家在不同店铺间切换，订单、刊登、库存、评价、退货都按当前店铺过滤（真实分区）。
  • 适用角色：所有角色。
  • 前置条件：场景中有多家店铺（如「多店公司化」）。

  1. 点击顶栏店铺名（带国旗，红框）。下拉列出所有店铺，每家显示「rFBS · N 单 · N 差评」。

  2. 点选另一家店铺，右上角提示「已切换至『店铺名』」，经营总览的 KPI、待办、趋势图都换成该店数据。

  3. 进入「订单履约」，列表只显示该店订单。

1.4 切换角色

  • 目的：不同岗位只看到自己需要的页面、只能执行自己权限内的动作。
  • 适用角色：所有人（一般由老板为团队成员说明各自角色）。
  • 前置条件：无。
角色 下拉提示 可见页面数 主要职责
老板 全权限 · 看周报 26 全部页面与动作；唯一可审批
运营 选品刊登履约 24 选品、刊登、定价、审单、客服、推广
仓管 仓配发货退货 9 采购完成、面单、发货、补货、退货
客服 评价问答退货 7 评价、问答、买家聊天、退货
财务 对账结算利润 12 利润定价、财务对账、店铺健康、推广与价格

  1. 点击顶栏 「角色」（红框），下拉列出 5 个角色及职责提示。

  2. 选「仓管」，右上角提示「当前角色：仓管」，头像变为「仓」。把鼠标移到侧栏上可以看到只剩仓管可见的分组与页面。

  3. 仓管尝试打开无权页面（例如通过命令面板去「财务对账」）时，系统提示「当前角色『仓管』无权访问『财务对账』」，页面不会切换。

  4. 「财务」角色的侧栏：利润定价、财务对账、店铺健康，以及推广活动、价格竞争、平台集成、数据连接等。

  5. 「客服」角色的侧栏：客服评价、客服收件箱、退货异常，以及订单（只读）等。

注意：角色控制的是「看得到什么、能点什么」。审批中心的「通过 / 驳回」只有老板能操作（见第十一部分）。

1.5 安装并连接 OzonFlow 连接器扩展（免密钥接入真实店铺）

  • 目的：没有 Api-Key 也能把 Ozon 卖家后台的真实订单、结算、商品数据带进 OzonFlow。
  • 适用角色：老板、运营、仓管、财务（谁登录卖家后台，谁装扩展）。
  • 前置条件：使用 Chrome 或 Edge 浏览器；有 Ozon 卖家后台登录账号。

  1. 进入侧栏「自动化与集成 → 数据连接」。未安装扩展时，第一张指标卡显示「浏览器插件 · 未安装」（红框）。

  2. 在「① Ozon 卖家后台直连」卡片里点 「OzonFlow 连接器插件」 链接（红框）下载 ozonflow-connector.zip，解压得到 ozonflow-connector 文件夹。

  3. 在浏览器地址栏打开 chrome://extensions（Edge 为 edge://extensions），打开右上角 「开发者模式」（红框），再点左上角 「加载未打包的扩展程序」（旧版浏览器显示为「加载已解压的扩展程序」，红框），选择解压出的文件夹。列表中出现「OzonFlow 连接器 1.0.0」即安装成功。

  4. 点击浏览器工具栏里的 OzonFlow 连接器图标，弹窗显示已捕获的订单 / 结算 / 商品数量，以及「打开 Ozon 卖家后台」「打开 OzonFlow 同步」「清空已捕获数据」三个按钮。

  5. 回到 OzonFlow「数据连接」页（刷新一次），第一张卡变为 「已连接 v1.0.0」（红框）。

  6. ⚠ 人工完成：在同一浏览器里正常登录 Ozon 卖家后台，依次打开 订单、财务（结算 / 交易）、商品列表 页面，扩展会在后台页面右下角显示已捕获数量（系统不会、也不能绕过 Ozon 登录）。

  7. 回到「数据连接」，点 「从插件同步」（红框）。

    结果：已捕获数据时，订单并入「订单履约」（含状态、发货截止时间、临期标红），结算按订单号并入「财务对账」，并提示同步数量。还没有在卖家后台捕获到数据时，会提示「插件还没有捕获数据：请先在 Ozon 卖家后台打开订单或财务页面」，如下图：

  8. 点 「刷新插件状态」 可重新读取扩展的捕获计数，提示「插件状态已刷新」。

1.5.1 不装扩展：报表导入

  1. 在 Ozon 卖家后台「订单 → 导出」或「财务 → 报告」下载 CSV / Excel。在「② 报表导入」卡片点 「选择文件」（红框），选择下载的文件。

  2. 系统按俄文表头（Номер отправления、Статус、Дата отгрузки 等）识别为「订单」报表，导入记录显示时间、文件名、类型、识别行数和结果，右上角提示导入结果。

  3. 再导入财务报表（表头含 ID операции、Тип начисления），识别为「结算」，并入财务对账。

  4. 打开「订单履约」，导入的订单出现在列表顶部（订单号为 Ozon 发货单号，剩余时效按「Дата отгрузки」计算）。

1.5.2 物流轨迹与数据导出

  1. 「④ 物流轨迹公开查询」卡片点 「刷新全部轨迹」，经扩展调用菜鸟国际公开查询接口（无需 Key）。

    完成后提示「已查询 N 个运单，M 个有轨迹」；查不到轨迹的单号显示「暂无轨迹」，可点单号打开菜鸟查询页人工核对。

  2. 「⑦ 给 AI Agent 用」卡片点 「导出经营数据 JSON」，浏览器下载 ozonflow-state.json，交给 node server/mcp-ozonflow.js --state ./ozonflow-state.json 后，AI 助手即可查询订单、利润、健康分与对账差异（写操作只生成待审批建议）。

1.6 侧栏、三级菜单与使用手册入口

  1. 默认是收起的图标侧栏，每个分组图标右上角的红色数字是组内待办合计。

  2. 鼠标移到侧栏上自动展开，显示 6 个分组及页面名；点分组标题可折叠 / 展开。

  3. 进入「订单履约」「客服评价」「退货异常」时，下方出现三级菜单（如 待审核 / 待采购 / 待发货 / 超时风险），点击直接带筛选进入。

  4. 点侧栏底部 「固定侧栏」，侧栏常驻展开；再点「取消固定」恢复悬停展开。

  5. 侧栏底部 「使用手册」 和顶栏 「?」 图标都会在新标签页打开本手册的网页版。

第二部分 每日开工

2.1 看经营总览

  • 目的：开工 1 分钟了解今天最要紧的事。
  • 适用角色：所有角色（内容按角色与当前店铺显示）。
  • 前置条件：已选定店铺。

  1. 顶部焦点区一句话给出今日重点（例如「今天先处理 3 单临近超时，4 项待审批」），下方显示 Agent 今日已处理数量、已启用 Agent 数，右侧是「AI 指令台」与「一键跑全部 Agent」。

  2. KPI 卡（红框）：今日订单、待发货（含待采购）、超时风险（距截单 < 6h）、预估毛利（已扣退货拨备）、差评 / 退货。

  3. 「今日待办」（红框）按风险排序：高风险审批、超时备货、待审单、缺货待采、差评待回、退货异常、物流轨迹异常、1★ 待升级、资金异常、刊登待处理。每项右侧按钮直达对应页面与筛选。

  4. 点顶栏 铃铛，弹出紧急事项汇总（超时 / 差评待回 / 退货异常）。

2.2 处理今日待办

  1. 在待办里点「N 笔超时备货」右侧的 「去处理」（红框）。

  2. 直达「订单履约 · 超时风险」，只显示距截单 < 6 小时的订单，按第三部分处理。

  3. 回到总览，点「N 项高风险动作待审批」右侧的 「去审批」（红框）。

  4. 直达审批中心待审批列表（处理方法见第十一部分）。

建议的每日顺序：超时风险 → 待审批 → 待审单 / 待采购 → 差评 → 退货 → 物流异常 → 刊登。

第三部分 订单履约（审核 → 采购 → 面单 → 发货 → 运单号回传）

  • 目的：把 Ozon 新订单在截单前发出，避免逾期发货率超标。
  • 适用角色：运营（审单、面单、发货）、仓管（采购完成、面单、发货）、老板；客服只读。
  • 前置条件：订单已通过扩展同步、报表导入或「同步订单」进入系统；物流渠道已连接。

订单状态流转：待审核 → （待采购）→ 待发货 → 已发货；剩余时效 ≤ 6 小时且未发货的订单自动标为「超时风险」。

3.1 同步订单

  1. 进入「订单履约」，点 「同步订单」（红框）。

  2. 右上角提示「已同步 N 笔新订单」，新订单以「待审核」状态出现在列表顶部，等待审单。

说明：免密钥模式下，真实店铺订单以扩展同步或报表导入为准（见 1.5）。「同步订单」按钮在当前经营场景的业务数据集中，按本店在售商品生成新订单并扣减库存，适合团队熟悉流程；接入 Api-Key 后改为调用 /v3/posting/fbs/unfulfilled/list 拉取真实订单。

3.2 审核订单

  1. 点筛选签 「待审核」（红框）。

  2. 只显示待审核订单，每行操作列有「审单」。

  3. 核对金额、买家留言后点某一行的 「审单」（红框）。

  4. 提示「已通过审单 订单号」，订单按规则匹配物流并转入「待发货」（库存不足会转「待采购」）。

  5. 剩余订单点 「一键审单」（红框）批量处理。

  6. 提示「自动审单完成 · 处理 N 笔订单」，待审核清零。规则：金额 < 5000₽ 且无买家留言自动通过；不满足的留给人工。

3.3 采购（缺货订单）

  1. 点筛选签 「待采购」（红框）。

  2. 列表为本地仓库存不足的订单。

  3. ⚠ 人工完成：在 1688 下单采购（1688 开放平台未接入前，下单需在 1688 完成）。到货后回到这里点 「采购完成」（红框）。

  4. 提示「已标记采购完成」，订单转「待发货」，本地库存与在售库存同步 +5。

单笔采购金额 ≥ ¥1000 的补货会进入审批中心。

3.4 申请面单

  1. 点筛选签 「待发货」（红框）。

  2. 未取号的订单显示「面单」，已取号的显示「发货」。

  3. 点 「面单」（红框）为订单申请运单号。

  4. 提示「运单号 YT…CN」，自动化列新增「已取号」，按钮变为「发货」。未分配物流的订单会先按重量自动匹配（≤500g 云途、>500g 燕文）。

    ⚠ 人工完成：免密钥模式下运单号由 OzonFlow 生成并记录，用于内部跟踪；实际面单请在物流商系统或 Ozon 后台下单打印，并以物流商返回的真实单号为准。

  5. 点 「批量申请面单」（红框）一次处理全部未取号订单。

  6. 提示「已批量申请面单 × N」。

3.5 查看订单详情与发货

  1. 点击订单行任意位置（操作列以外，红框）。

  2. 右侧打开订单详情抽屉：商品信息、买家、收货城市、订单金额、采购成本、预估毛利与毛利率、物流渠道、运单号、剩余时效、自动化轨迹（每一步时间与内容）。

  3. 抽屉底部「快捷操作」按订单状态显示 手动审单 / 匹配物流 / 采购完成 / 申请面单 / 确认发货。打包完成后点 「确认发货」（红框）。

  4. 提示「订单号 已发货 · 运单号」，状态变为已发货，轨迹记录「提交平台发货」。按 Esc 或点 × 关闭抽屉。

  5. 也可以直接在列表操作列点 「发货」（红框）。

    ⚠ 人工完成：免密钥模式下「发货」只更新 OzonFlow 状态。请在 Ozon 卖家后台把该订单标记为已发货；接入 Api-Key 后会通过 /v4/posting/fbs/ship 自动提交。

  6. 点 「已发货」 签查看已发出订单及运单号。

  7. 搜索框输入订单号 / 买家 / SKU 即时过滤。

3.6 上传（回传）运单号

  • 目的：已发货订单必须把运单号回传给 Ozon，否则 Ozon 后台没有轨迹，会计入渠道 / 运单错误率。
  • 适用角色：运营、仓管、老板。
  • 前置条件：订单已发货且有运单号。

  1. 打开「订单履约 → 时效物流」，找到「rFBS 状态与运单号回传」卡片。「Ozon 状态」为「未回传」的行有 「回传运单号」 按钮（红框）。

  2. ⚠ 人工完成：先在 Ozon 卖家后台订单详情中填写该运单号并保存；再回到 OzonFlow 点「回传运单号」，提示「运单号已回传」，状态更新为已回传，方便团队对账跟踪。

  3. 多单时点 「全部回传」（红框），提示「已回传 N 单」。

接入 Api-Key 后，这一步走 /v2/fbs/posting/tracking-number/set 自动回传，无需再到后台手填。

3.7 超时风险处理

  • 目的：抢救距截单不足 6 小时的订单，控制逾期发货率（Ozon 阈值 ≤10%，7 天窗口）。
  • 适用角色：运营、仓管、老板。
  • 前置条件：存在超时风险订单。

  1. 「订单履约 · 超时风险」（红框）：剩余时效标红。逐单按 3.4–3.5 申请面单并发货。

  2. 批量抢救：打开「财务风控 → 店铺健康」，点 「一键抢救临期订单」（红框）。

  3. 超时抢救 Agent 执行「审单 → 面单 → 发货」，缺货的标记采购或送审取消，提示「超时抢救 · 处理 N 笔」。

  4. 节假日前在「时效物流」检查「仓库休息日对截单期影响」，按建议在休息日前发出或安排值班。

  5. 实在来不及的缺货单，取消申请会进入审批中心（取消会计入取消率），由老板决定。

常见问题（订单）

  • 点「面单」后运单号和物流商的不一致？ 免密钥模式下系统生成的是内部跟踪号，请以物流商真实单号为准，在 Ozon 后台填写真实单号。
  • 为什么「一键审单」后还有订单没过？ 金额 ≥ 5000₽ 或有买家留言的订单需要人工审核。
  • 仓管看不到「审单」？ 审单属于运营权限；仓管负责采购完成、面单、发货。
  • 订单详情里看不到「确认发货」？ 只有已有运单号且未发货的订单才显示该按钮，先申请面单。

第四部分 商品上架与定价利润

4.1 选品与利润测算

  • 目的：上架前算清到手净利，避免卖一单亏一单。
  • 适用角色：运营、老板（财务可看利润定价）。
  • 前置条件：无。

  1. 「商品增长 → 智能选品」，在商品卡上点 「测算利润」（红框）。

  2. 右侧「一键利润测算」面板载入该商品：Ozon 售价、1688 采购价、重量、汇率、平台佣金、头程物流、手续费 + 退货拨备、到手净利、利润率。

  3. 按实际修改售价 / 采购价 / 重量，点 「一键测算利润」（红框）。

  4. 提示「测算完成 · 净利 N ₽ · 利润率 N%」。

  5. 利润达标后点商品卡上的 「认领」（红框）。

  6. 提示「『商品名』已加入刊登草稿」，并进入「刊登上架」。

4.2 利润定价（三情景）

  1. 「财务风控 → 利润定价」，左侧「选品 / 在售 · 快速测算」点某商品的 「测算利润」（红框）。

  2. 右侧「情景对比」给出 日常价 / 跟卖价（售价 × 95%）/ 活动价（售价 × 90%） 三种情景的佣金、头程、手续费 + 拨备、净利与利润率；亏损情景标红。

  3. 在「共享费率」修改汇率 ¥→₽、头程 ¥/kg、支付手续费、退货拨备后点 「保存费率」（红框）。

  4. 提示「共享费率已保存」，全站利润测算、对账与 Agent 统一用新口径。

佣金阶梯（按售价）：≤500₽ 15%；500–2000₽ 12%；>2000₽ 10%。头程 = max(80₽, 重量 kg × 头程单价 × 汇率 + 45₽)。

4.3 刊登上架

  1. 「商品增长 → 刊登上架」，状态签（红框）：全部 / 草稿 / 映射中 / 待发布 / 已发布 / 审核失败。

  2. 点 「推进映射」（红框）补齐类目映射与俄语属性。

  3. 审核失败的商品点 「修复」，提示「已修复并回到待发布」。

  4. 待发布商品点 「发布」，提示「已发布上架 · Ozon SKU …」，生成在售商品与库存记录。

  5. 点 「批量发布待发布」 一次发布全部就绪商品。

    ⚠ 人工完成：免密钥模式下发布只在 OzonFlow 内生成在售记录，请在 Ozon 卖家后台创建 / 更新商品卡；接入 Api-Key 后经审批走 /v3/product/import。

  6. 内容质量：「内容合规」页对内容分低的商品点 「AI 补齐」，生成标题 / 属性 / 富文本草稿（人工确认后再同步到 Ozon）。

  7. 「俄语标题公式与改写」卡片点 「采用」，标题更新为建议标题。

4.4 市场选品与换供

  1. 「市场选品」多维评分表点 「认领进刊登」。

  2. 「以图搜货 / 断货换供」点 「切换货源」，货源与采购价更新、利润重算。

4.5 素材工坊：生成商品短视频

  1. 「素材工坊」选择商品与卖点后，点 「生成视频」，在浏览器本地合成主图轮播 + 俄语卖点字幕的短视频。

常见问题（商品）

  • 净利为负还能认领吗？ 能，但利润守门 Agent 会标记并给出建议价。
  • 为什么证书过期的商品发布不了？ 刊登 Agent 会拦截证书缺失或过期的商品，先在内容合规里登记证书。

第五部分 库存补货

  • 目的：防止断货与超卖。
  • 适用角色：仓管、老板（运营可看）。
  • 前置条件：已有在售商品与库存记录。

  1. 「订单履约 → 物流与库存」点 「立即同步」（红框）。

  2. 提示「库存同步完成 · 更新 N SKU · 低库存 N」，本地仓数量同步到 Ozon 在售库存。

  3. 低库存 SKU 点 「补货 +50」（红框）。

  4. 提示「商品 已补货 +50 · 本地 N」。

    ⚠ 人工完成：在 Ozon 后台同步修改在售库存（接入 Api-Key 后走 /v2/products/stocks）。

  5. 未连接的物流渠道点 「连接」，提示「渠道 已连接」。

  6. 「供应链库存」海外仓补货计划点 「生成补货单」：金额 ≥ ¥1000 时提示「补货金额 ¥N，已进审批中心」。

  7. 多店共享库存点 「全部重分配」，按各店近 7 天销量比例分配并预留 10% 安全量。

  8. 「自动化规则」点 「立即执行规则引擎」，审单 / 物流匹配 / 采购 / 库存同步 / 取号规则执行。

  9. 每张规则卡右上角开关可启停（红框）。

第六部分 客服、差评与退货

6.1 回复评价与问答

  • 目的：及时用俄语回复差评与提问，降低差评占比。
  • 适用角色：客服、运营、老板。
  • 前置条件：评价 / 问答已同步。

  1. 「客服售后 → 客服评价 · 评价」，对差评点 「模板回复」（红框）。

  2. 提示「已回复评价」，按评分匹配俄语模板。

  3. 切换 「问答 Q&A」，点 「回答」，提示「已回答买家提问」。

  4. 切换 「俄语回复模板」，点 「复制」，模板复制到剪贴板。

  5. 「客服收件箱」按意图给出俄语建议回复，点 「发送」，提示「已回复 买家名」。

⚠ 人工完成：回复、回答、聊天在免密钥模式下只记录在 OzonFlow，请把回复内容粘贴到 Ozon 卖家后台对应评价 / 问答 / 聊天中发送；评价、问答、聊天接口还需要 Premium Plus 订阅。

6.2 差评预警升级

  1. 在「自动化 Agent」运行 「差评预警升级 Agent」（红框）。

  2. 1 星差评升级为理赔工单并联动退货队列，提示「差评预警升级 · N 条」。

6.3 退货处理

  • 目的：按状态机处理取消 / 退货 / 索赔：待处理 → 调查中 / 已同意 / 已拒绝 → 已退款 → 已关闭。
  • 适用角色：客服、仓管、运营、财务、老板。
  • 前置条件：存在退货单。

  1. 「退货异常 · 待处理」，点 「调查」（红框），提示「RT… → 调查中」。

  2. 核实后点 「同意」，提示「→ 已同意」。

  3. 在「已同意」中点 「退款」：金额 < 2000₽ 直接「→ 已退款」。

  4. 金额 ≥ 2000₽ 的退款提示「退款 N₽ 已提交审批中心」，需老板审批后执行。

  5. 不符合条件的申请点 「拒绝」，提示「→ 已拒绝」，留痕可追溯。

⚠ 人工完成：同意退款、拒绝等决定需在 Ozon 卖家后台退货页同步处理。

第七部分 财务对账

  • 目的：逐单比对 Ozon 结算与订单测算利润，找出佣金、物流、罚款、退货造成的利润漏损。
  • 适用角色：财务、老板。
  • 前置条件：结算数据已通过扩展或财务报表导入。

  1. 「财务风控 → 财务对账」，差异单逐笔核对后点 「标记已核」，提示「结算单号 已标记」。

  2. 罚款类差异（如逾期发货罚款）点 「发起申诉」，提示「申诉已进审批中心」。

  3. 点 「批量标记一致项」，差异 ≤ 30₽ 的已结算单批量标记。

  4. 切换 「全部」 查看所有结算单。

  5. 下方查看「回款日历与资金预测」（每月 15 日 / 月末两次回款估算）与「汇兑损益明细」（下单日 vs 结算日汇率）。

  6. 「收款主体与资金合规」清单逐项勾选完成（仅作自查，不构成税务或法律意见）。

第八部分 推广与价格竞争

8.1 价格竞争

  1. 「价格竞争」价格指数偏高的商品点 「按建议调价」：幅度 ≤ 10% 直接生效；> 10% 提示「改价幅度较大，已提交审批」。任何调价都不会低于利润底价。

  2. 「采购价变动 → 利润重算」点 「更新成本并重算」，提示新净利率。

  3. 「跨境 VAT 压力测试」切换 VAT 20%，查看各 SKU 净利率变化（仅压力测试，以正式法规为准）。

8.2 推广活动

  1. 「推广活动」亏损广告点 「暂停（审批）」，提示「暂停请求已进审批中心」。

  2. 点 「应用建议预算」，总预算不变，按「单件净利 × 转化率」重新分配。

  3. 「活动报名前利润测算」点 「报名」：活动后净利率高于底价直接报名；低于底价进入审批。

⚠ 人工完成：改价、暂停广告、报名活动审批通过后，在 Ozon 后台价格 / 广告 / 促销页面执行（广告接口需 Performance API 授权）。

第九部分 合规

  • 目的：避免因证书、标签、禁限售词、图片、商品卡合并违规被下架或罚款。
  • 适用角色：运营、老板。

  1. 「内容合规」禁限售词卡片点 「清洗文案」，提示「风险词已清洗」。

  2. EAC 证书即将到期 / 缺失的商品点 「登记证书 / 登记续期」，提示「证书已登记」。

  3. Честный знак 需贴标的商品点 「生成贴标任务」。

  4. 图片不合规的商品点 「生成合规图」（白底、无中文、≥900px）。

  5. 疑似盗图点 「发起投诉（审批）」，投诉进入审批中心。

  6. 「店铺健康」商品卡合并违规点 「生成整改任务」。

  7. 对误判的错误点 「申诉误判错误」，申诉进入审批中心。

第十部分 自动化 Agent 中枢

  • 目的：让 13 个专业 Agent 按规则自动处理重复工作，人只处理异常与审批。
  • 适用角色：所有角色可运行（老板 / 运营可开关）。
  • 前置条件：无。「旺季履约突击」「多店公司化」场景默认启用 9 个 Agent。

13 个 Agent：选品雷达、刊登过审、审单履约、超时抢救、1688 采购跟单、物流轨迹异常、利润守门、汇率佣金重算、俄语客服、差评预警升级、退货理赔、库存补货、周报汇报。

  1. 打开「自动化与集成 → 自动化 Agent」，顶部显示启用中 / 今日处理 / 专业 Agent 数，下方每张卡片是一个 Agent。

  2. 用卡片右上角 开关（红框）启用 / 停用，提示「已启用 / 已停用」。

  3. 点卡片的 「运行」 立即运行（停用的 Agent 也可手动运行），提示处理数量，卡片显示上次运行时间、今日处理数与活动日志。

  4. 点 「执行定时回合」 只运行已启用的 Agent（页面打开时系统每 45 秒自动执行一次）。

  5. 点 「一键跑全部 Agent」 按级联顺序运行全部 13 个：选品雷达 → 刊登过审 → 利润守门 → 汇率佣金重算 → 1688 采购 → 超时抢救 → 审单履约 → 物流轨迹异常 → 库存补货 → 俄语客服 → 差评预警 → 退货理赔 → 周报汇报。依次提示总处理数、级联明细与周报快照。

  6. 查看日志：页面底部「最近活动合流」（红框）汇总所有 Agent 的动作；每张卡片也有自己的活动日志。

  7. 经营总览顶部也有 「一键跑全部 Agent」。

注意：Agent 的高风险动作（改价 >10%、退款 ≥2000₽、采购 ≥¥1000、取消订单等）不会直接执行，而是进入审批中心。

第十一部分 审批流程

  • 目的：人在环把关高风险动作。
  • 适用角色：老板审批；其他角色可查看。
  • 审批阈值：改价 > 10% · 退款 ≥ 2000₽ · 采购 ≥ ¥1000 · 取消订单 · 暂停广告 · 低于底价报名 · 申诉 · 侵权投诉。

  1. 打开「工作台 → 审批中心」：顶部为待审批 / 已通过 / 已驳回 / 审计记录；列表列出风险等级、类型、事项、变更前 → 后、原因、发起方、时间。

  2. 核对后点 「通过」（红框），提示「已通过并执行：…」，动作立即生效并写入审计日志。

  3. 不同意点 「驳回」，提示「已驳回：…」。

  4. 切换 「已处理」 查看历史。

  5. 非老板角色（如运营）打开审批中心：通过 / 驳回按钮置灰，表格下方提示「当前角色可查看审批，切到『老板』角色后可通过或驳回」。

  6. 老板点 「批量通过」 一次处理全部待审批，提示「批量通过 N 项」。

  7. 页面底部「操作审计日志」记录每一次人工与 Agent 动作（时间、操作人、动作、对象、结果）。

常见问题

Q1：数据存在哪里？换电脑后还在吗？ 数据保存在当前浏览器的 localStorage（键 ozonflow_rfbs_v2）。换电脑或清缓存后需重新通过扩展同步或导入报表。「数据连接 ⑦」可导出经营数据 JSON 备份。

Q2：没有 Api-Key，哪些事情 OzonFlow 能做、哪些必须人工？ 读数据（订单、结算、商品、公开价格、物流轨迹）通过扩展和报表导入完成；所有写回 Ozon 的动作（发货、回传运单号、改价、上架、库存、回复、退款、取消、广告、报名活动）必须在 Ozon 卖家后台人工完成，见「阅读前须知」表格。

Q3：扩展装好了，「从插件同步」却提示没有捕获数据？ 需在同一浏览器登录 seller.ozon.ru，并打开订单、财务、商品列表页面让后台加载数据；然后点「刷新插件状态」再同步。

Q4：为什么点「通过」没有反应？ 只有老板角色能审批，其他角色按钮置灰。顶栏切到「老板」后再操作。

Q5：Agent 会不会擅自改价、退款？ 不会。超过阈值的动作都进入审批中心；低于阈值的（如改价 ≤10%）会自动执行并写审计日志，可在审批中心底部查看。

Q6：我改错了数据，怎么恢复？ 顶栏「↻」或「经营场景 → 重置当前场景数据」可恢复当前场景初始数据（会清除本场景所有改动）。

Q7：报表导入识别为「未识别」？ 确认文件是 Ozon 后台原始导出、表头为俄文（如 Номер отправления / Тип начисления），CSV 分隔符为分号或逗号均可。

Q8：页面右上角的提示一闪就没了？ 提示约 3 秒后自动消失，操作结果同时会体现在列表状态、审计日志或同步记录中。

五、财务风控

20. 利润定价（profit）

  • 页面用途：维护共享费率，按日常价 / 跟卖价 / 活动价三情景测算净利。
  • 入口路径：侧栏「财务风控 → 利润定价」；智能选品「打开利润定价 →」；刊登「测算」。
  • 页面区域说明
    • 共享费率（单位经济）：汇率 ¥→₽、头程 ¥/kg、支付手续费、退货拨备；佣金阶梯（≤500₽ 15% / 500–2000₽ 12% / >2000₽ 10%）；「保存费率」。
    • 选品 / 在售 · 快速测算：商品 / 售价 ₽ / 成本 ¥ / 「测算利润」。
    • 情景对比 · 跟卖价 / 活动价：日常价（当前售价）、跟卖价（× 95%）、活动价（× 90%）三张卡：售价、佣金率与金额、头程、手续费 + 拨备、净利、利润率（亏损标红）。
    • 自定义测算：售价 ₽、采购价 ¥、重量 g；「重新测算三情景」。
  • 数据来源：【本地计算】（净利 = 售价 − 采购成本 × 汇率 − 佣金 − 头程 − 手续费 − 退货拨备 − 包材 − 广告）。
  • 适用角色：老板、运营、财务。
  • 关联页面：智能选品、刊登上架、价格竞争、财务对账、自动化 Agent（利润守门、汇率佣金重算）。

1. 背景

Ozon 是俄罗斯第一大电商平台。中国卖家多以 rFBS（Realistic FBS，卖家自发货跨境直发） 模式经营：买家下单后，卖家需在截单时效内完成审单、1688 采购、打包、申请面单、交给跨境物流并回传运单号。这条链路跨越 Ozon 卖家后台、1688、物流商系统、Excel 利润表和多个聊天工具，信息分散、全靠人盯。

2025–2026 年平台规则持续收紧：错误指数自 2026-09-22 起重新计算并分档罚款；财务旧接口 2026-09-08 停用；评价 / 问答 / 聊天接口需要 Premium Plus 订阅；同一执照最多开 6 家店。卖家需要一套以 履约时效、利润、店铺健康 为核心、能被团队分工使用、且高风险动作可控的经营系统。

3. 痛点

  1. 时效焦虑：rFBS 截单时效短，休息日、缺货、面单没取都会导致逾期，直接推高错误指数与罚款。
  2. 利润算不清：佣金阶梯、汇率、头程、退货拨备、广告、VAT 叠加，跟卖与活动价常常亏本而不自知。
  3. 工具割裂：卖家后台、1688、物流商、Excel、聊天工具来回切换，团队协作靠截图和口头。
  4. 俄语客服门槛：差评、问答、聊天需俄语回复，响应慢导致评分下降。
  5. 对账黑盒：结算单罚款、物流费差异、汇兑损益难以逐单核对。
  6. API 门槛：Api-Key 申请、Premium Plus 订阅、接口频繁废弃迁移，小卖家难以接入。
  7. 自动化不可控：直接让脚本改价、退款、采购风险高，缺少审批与审计。

7.1 工作台

用户故事

  • 作为老板，我打开系统就能看到今天最该先做的事，按风险排好序。
  • 作为老板，我用一句中文就能批量处理（如「处理所有超时订单」），并先看到影响范围。
  • 作为老板，所有高风险动作都要经我审批，可追溯。

功能：经营总览（5 KPI、今日待办、7 日趋势、热销 TOP5、一键跑全部 Agent）；AI 指令台（22 条示例、执行计划预览、确认执行）；审批中心（待审批 / 已处理、批量通过、审计日志）；经营周报（分店铺 / SKU 汇总、导出）。

业务规则

  • 待办排序：高风险审批 > 超时 > 待审单 > 缺货 > 差评 > 退货 > 轨迹异常 > 资金 > 刊登。
  • 审批阈值：改价 > 10%、退款 ≥ 2000₽、采购 ≥ ¥1000、取消订单、暂停广告、低于底价报名活动、申诉、侵权投诉。
  • 仅老板可通过 / 驳回；其他角色按钮置灰并提示。
  • AI 指令台非只读指令写入审计日志。

验收标准

  • 总览 KPI 与订单页筛选数一致；待办按钮跳转到对应页面与筛选签。
  • 输入「把毛利低于 20% 的商品提价 8%」出现执行计划，确认后生成改价或审批项。
  • 审批通过后状态变为已处理，审计日志新增一条。

7.2 订单履约

用户故事

  • 作为仓管，我希望订单自动审单、匹配物流、取号，我只负责打包发货。
  • 作为运营，我要第一时间看到 6 小时内要超时的订单。
  • 作为仓管，休息日前要知道哪些单必须提前发。

功能：订单 6 状态筛选 + 搜索；一键审单；批量申请面单；订单抽屉与自动化时间线；6 条 IF / THEN 规则；休息日截单影响；运单号回传；渠道运价比较；报关一致性；IML 退货处置；物流渠道；库存同步与补货；多店共享库存防超卖；rFBS / FBO / FBP 决策；海外仓补货与滞销。

业务规则

  • 自动审单：金额 < 5000₽ 且无买家留言。
  • 物流匹配：≤ 500g 云途俄线，> 500g 燕文经济。
  • 审单后本地库存不足 → 待采购；采购完成 → 待发货。
  • 超时风险：剩余时效 ≤ 6h 且未发货。
  • 运费 = 单价 × 重量 + 挂号费 ¥12；报关申报价按订单价 80% 校准。
  • 共享库存按近 7 天销量比例分配，预留 10%。
  • 补货单金额 ≥ ¥1000 进审批。

验收标准

  • 「一键审单」后符合规则的订单进入待发货并带「已审单」「已匹配物流」标签。
  • 「批量申请面单」后订单生成运单号与「已取号」标签。
  • 「发货」后状态为已发货，总览待发货数同步减少。
  • 发货 / 运单号回传在接入 Api-Key 前明确提示需在卖家后台完成。

7.3 商品增长

用户故事

  • 作为运营，我要知道哪个品值得做，上架前就算清利润。
  • 作为运营，刊登前自动检查属性、证书、禁限售词和图片规范。
  • 作为运营，跟卖压价时不能跌破底价，大幅调价要老板批。

功能：智能选品（爆款 / 蓝海 / 跟卖、利润测算、认领）；市场选品（5 维评分、节点倒推、断货换供）；刊登上架（草稿 → 映射 → 待发布 → 已发布）；素材工坊（白底主图、视频、富内容 JSON）；内容合规（内容评分、标题公式、EAC、Честный знак、禁限售词、图片规范、问答回写、防盗图）；价格竞争（价格指数、跟卖、底价、比价、成本栈、VAT、佣金重排）；推广活动（ДРР / ROI、亏损暂停、预算分配、活动利润）。

业务规则

  • 选品评分权重：销量 25 · 净利率 30 · 重量 10 · 竞争度 15 · 趋势 20；红线品直接 0 分。
  • 备货截止 = 节点日期 − 26 天。
  • 内容评分：俄语标题 25、类目属性 25、图片 20、富文本 10、视频 10、合规 10。
  • 证书到期前 60 天提醒；缺失或过期的商品被刊登 Agent 拦截。
  • 图片：≥ 5 张、主图白底、无中文与水印、边长 ≥ 900px。
  • 价格指数偏红 = 比全网最低高 10% 以上；建议价不低于底价（净利率 20%）。
  • 整体 ДРР 目标 ≤ 15%；亏损广告暂停需审批；低于底价的活动报名需审批。

验收标准

  • 选品「测算利润」后右侧显示净利与利润率；「认领」后进入刊登草稿并跳转。
  • 刊登「批量发布待发布」后状态为已发布。
  • 价格竞争「按建议调价」幅度 > 10% 时生成审批项，否则直接生效。

7.5 财务风控

用户故事

  • 作为财务，我要逐单看结算和预期利润的差异，找出罚款和多扣的物流费。
  • 作为老板，我要知道错误指数离下一档还差多少、要罚多少钱。

功能：共享费率与三情景测算；逐单对账、申诉、回款日历、汇兑损益、合规清单；服务质量指标、错误指数分档与罚金、风险分、临期抢救、多账号、商品卡合并违规。

业务规则

  • 佣金阶梯：≤ 500₽ 15%，500–2000₽ 12%，> 2000₽ 10%。
  • 跟卖价 = 售价 × 95%，活动价 = 售价 × 90%。
  • 头程运费 = max(80, 重量 kg × 头程 ¥/kg × 汇率 + 45) ₽。
  • 对账差异：实际净利偏离预期超过 30₽。
  • 回款：每月 15 日与月末两次估算。
  • 错误指数：≤ 5% 正常，5.1–10% 一档，> 10% 二档。
  • 风险分权重：取消率 30、逾期 25、错误指数 20、差评 15、退货 10；≥ 60 时申诉 / 下架 / 批量改价强制审批。

验收标准：修改费率保存后，选品、价格竞争、利润定价净利同步更新；对账「发起申诉」生成审批项。

用户故事

  • 作为老板，我希望重复劳动交给 Agent，按顺序自动跑完一轮，高风险的留给我批。

业务规则

11. 数据与集成

11.1 免密钥模式（当前）

  • 连接器：Chrome 扩展（ID 以安装为准），在用户已登录的卖家后台页面读取接口返回，app 页面经 bridge 获取数据并显示「已连接 v1.0.0」。
  • 报表导入：自动识别订单报表与财务报表，记录识别行数。
  • MCP：node server/mcp-ozonflow.js，工具 ozonflow_summary、list_orders、list_products、shop_health、finance_diffs、compete_prices、daily_brief、propose_price_change；改价建议写入 ozonflow-pending.json，导入后全部进审批。

11.2 Api-Key 模式（规划）

  • 部署：OZON_CLIENT_ID=… OZON_API_KEY=… ALLOW_ORIGIN=… PORT=8787 node server/ozon-proxy.js；平台集成页切换「代理」模式并「测试连接」。
  • 写操作白名单 WRITE_ALLOW，并叠加审批中心。
  • 端点迁移：shipOrder 用 v4；财务改用 /v1/finance/accrual/*。
